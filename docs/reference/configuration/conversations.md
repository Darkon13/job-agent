# `profiles[].conversations`

Политика чатов: чтение разрешено всегда, мутации — только явными флагами.
Полный контракт — в [Conversation API](../../conversation-api.md).

## Пример

```json
"conversations": {
  "allow_send": true,
  "allow_mark_read": true,
  "answer_known": true
}
```

| Поле | Тип | Обяз. | По умолчанию | Описание |
|---|---|---|---|---|
| `allow_send` | bool | нет | `false` | Разрешить отправку сообщений и ответы на опросники из чата. |
| `allow_mark_read` | bool | нет | `false` | Разрешить менять read-state диалогов. |
| `answer_known` | bool | нет | `false` | Автоответ на опросник только точным reviewed-блоком из `answer_sets`: текст выбранной кнопки отправляется обычным сообщением. Требует `allow_send`. Неизвестный, неоднозначный или устаревший вариант остаётся человеку; `send_event`-кнопки так не обрабатываются. |

## Что происходит без флагов

- `conversation.sync` читает каталог и историю, сохраняет вакансию,
  работодателя и ссылку диалога;
- непрочитанные остаются непрочитанными;
- задачи `conversation.send`/`conversation.mark_read` завершаются отказом
  политики, не меняя платформу.

## Follow-up таймеры

Отложенные сообщения — не cron, а durable одноразовые `FollowUp`-таймеры
(источник истины). Job `conversation.follow_up.select` выбирает один диалог и
создаёт таймер; перед отправкой worker повторно читает диалог и отменяет
таймер при новом входящем, закрытии диалога или terminal-состоянии отклика.
Параметры выбора — в [jobs](jobs.md#conversation-follow_up-select).
