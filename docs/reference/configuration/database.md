# `database`

Хранилище состояния. Job Agent рассчитан на SQLite; переход на PostgreSQL не
меняет доменные контракты, но пока не реализован.

## Пример

```json
"database": {
  "driver": "sqlite",
  "path": "./data/job-agent.db"
}
```

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `driver` | string | **да** | Драйвер БД. Поддерживается `sqlite`; другое значение отклоняется на старте. |
| `path` | string | **да** | Путь к файлу базы. Каталог создаётся при миграции. |

## Связанные команды

- `job-agent -migrate-up <config>` — применяет миграции перед стартом сервиса;
- `job-agent-migrate` — отдельный одноразовый контейнер/процесс миграций;
- `job-agent db backup <file>` — согласованный снимок с проверкой integrity;
- `job-agent db restore --force <file>` — заменяет файл после проверки
  источника и удаляет устаревшие `-wal`/`-shm`.

## Примечания

- Приложение проверяет точную версию схемы и `dirty`-состояние и останавливается
  с подсказкой команды миграции, а не мигрирует неявно.
- WAL-файлы (`-wal`, `-shm`) являются частью рабочей БД; резервное копирование
  выполняется только командой `db backup`.
